## Live activity line on every task row (2026-08-25)

- [x] Every task row on the Board (and Queue — both use `TaskRow`) now carries a second, dimmed mono line under the title saying what its agent is doing **right now**: `Read runs routes and api client`, `Write notes.md`, `Subagent · Explore codebase`, or the sentence the agent just said. A small pulsing accent dot marks it as live. Rows with no live agent look exactly as before — the line only exists while a run is live and non-idle.
- Source is the **claude session transcript**, not the PTY bytes. `server/src/claude/activity.ts` tails each live run's `transcript_path`, and each assistant record yields its last renderable block: a `tool_use` rendered the way the terminal narrates it (`describeTool`) or the assistant's own text, truncated to 110 chars. Sidechain (subagent) records are skipped — the parent's own `Subagent · …` line already says one is running.
- Transport: `ServerEvent` `run.activity` carrying `RunActivity {runId, taskId, text, kind, at}` over `/ws/events`, plus `GET /api/runs/activity` as the page-load/reconnect snapshot. `text: null` means "this run is no longer live" and the client deletes the entry, so nothing stale lingers on a row in review. Nothing is persisted — it is a live signal, not history.
- Self-healing by design: the watcher re-reads the live-run set from storage every 4s rather than being pushed at from the hooks, so a dropped `SessionStart` curl or a mid-run restart cannot leave the Board permanently blank. The DB read is gated on `sessions.liveCount() > 0 || tails.size > 0`, so an idle server never touches storage for this.
- Tail is incremental and bounded: first read seeks to the last 512KiB (a resumed run shares the earlier session's whole transcript), truncation/replacement resets the offset, a jump larger than the catch-up window re-seeks, and a half-flushed trailing line is carried to the next read (dropped if it grows past the window). Poll 1.2s; an unchanged line emits nothing.
- Verified: `npm run typecheck` + `npm run build` clean. `describeTool`/`activityFromLine` exercised against a real 283-line transcript (38 activities extracted, all legible) plus 11 unit cases incl. empty args, mcp-prefixed names, sidechain skip, garbage/partial JSON, tool-beats-text-in-one-message, and the 110-char cut. `ActivityWatcher` driven through append / duplicate-suppression / batch-collapse / half-written line / truncation / 700KB jump / run-ended-clears, all correct. End-to-end on an **isolated second instance** (port 5199, own data dir — the live server was NOT restarted, it was running this session's own worker): real haiku workers produced `Write notes.md` → `Read notes.md and list the directory` → final text → `null` on idle, confirmed on the WS and in the snapshot route, and rendered on the Board in the browser with two concurrent agents narrating.
