# Decision log

- **2026-08-24 — Restart button + follow-up injection fix**: header shows a server status pill (green up+uptime / amber restarting/offline, driven by the /ws/events connection) + a ⟳ Restart button (POST /api/server/restart spawns a detached copy of the process and exits — self-supervising one hop; warns if workers are running since restart fails them). FIX: followUp/review-fix/apply-review no longer INJECT into a finished (idle) interactive claude prompt — injected text does not reliably submit there, which wedged a task at running with a dead terminal. Idle sessions are now KILLED and the task RESPAWNED with the message+prior-summary in the prompt (reliable). A genuinely mid-turn session rejects follow-ups (wait for review).

- **2026-08-24 — Apply review fixes (backfill)**: `POST /api/tasks/:id/apply-review` + drawer button on review/done/failed tasks. Respawns a worker (via followUp) with the stored review findings to apply, or — if the task was never reviewed — instructs a self-review-and-fix; the result then goes through the normal review-fix loop. Lets old tasks (pre-loop, or reviewed-but-unfixed) be brought up to standard.

- **2026-08-24 — work → review → work loop**: the adversarial review no longer just attaches findings and ends. When it finds blocker/major issues AND the worker session is still live AND the task is still in review (human hasn't taken over), the orchestrator feeds the findings back into the SAME live worker session (via followUp → reactivate idle → running); the worker fixes them, Stops, and is RE-reviewed. Bounded by `review.maxRounds` (default 2) so an unfixable finding can't loop forever; clean/minor-only/cap/human-takeover settles into the human review queue as before. review.ts now returns structured {verdict, findings}. Note: review diffs `git diff HEAD`, so it sees ALL uncommitted changes in the repo, not only this worker's — fine when the worker dominates the diff, noisy on an already-dirty tree.

- **2026-08-24 — Sentry tags + scope diagnosis**: the sourcemap-upload token (sntryu_, org:read only) 403s on issues — sync needs an auth token with project:read + event:read; the error now says so exactly. Import pulls per-issue TAGS (environment/release/transaction/level + custom, best-effort via /issues/:id/tags/) into the task description, and sets the task CATEGORY from a configurable Sentry tag key (sentry.categoryTag; blank = issue level like Error/Warning). Degrades silently if the tags endpoint is unpermitted.

- **2026-08-24 — Per-task review override**: tasks get a nullable `review` field — null = use the global `review.enabled` setting, true = force review, false = skip (for small/trivial tasks). Selector in the create form + drawer ("default / review this / skip"); agents can pass `review:false` on create. Migration 8. `reviewCompletedRun` gates on `task.review ?? settings[review.enabled]`.

- **2026-08-24 — Worker self-review + file I/O**: (1) Every worker change gets an ADVERSARIAL REVIEW pass before landing in review — server-orchestrated headless `claude -p` on the git diff (Fable, falling back to Opus 5 xhigh when Fable is unavailable, cached), structured findings shown in the task drawer. Config `review.enabled` (default on) / `review.model`. server/src/claude/review.ts. Chosen over a worker-spawned subagent because model+effort cannot be pinned reliably from inside a spawned session. (2) Per-task file space (`TM_ARTIFACTS_DIR`) is now BIDIRECTIONAL: users drag-drop uploads (screenshots/data) into the drawer as agent INPUTS, and agents save deliverables there as OUTPUTS — one folder, listed/downloadable/removable in the drawer. @fastify/multipart, 25MB/file. Files deleted with the task.

- **2026-08-24 — Per-repo git buttons**: Repos page has a git status chip (branch, N changed, ↑ahead) plus **Commit** (`git add -A` then commit — message written by `claude-opus-5` from the staged diff via headless `-p`, read-only tools; Co-Authored-By Opus 5 trailer) and **Push** (`git push`, sets upstream on first push). One op per repo at a time; endpoints `/api/repos/:id/{git,commit,push}`, audited as repo.changed. server/src/git.ts.

- **2026-08-24 — Task categories + Board filtering/grouping**: free-text `category` on tasks ("UI", "Estimator", "Auth"…). AGENTS invent and fill them — via `category` on agent-create, `POST /api/agent/tasks/:id/category`, and Analyze runs assign one per task (top-level `categories` in the structured output, applied server-side, never clobbering a human/worker value). Humans edit via the create form + slide-over (datalist of known labels). Board has filter bar (repo / provenance{human,agent,sentry,analyze} / category) + group-by (status/category/repo). Migration 6 adds the column. Follow-up field + per-task deliverable files (TM_ARTIFACTS_DIR) also shipped this session.

- **2026-08-24 — Role model split** (user policy): workers = `claude-opus-5` (heavy implementation), analysis = `claude-fable-5`, orchestrator-tier agents = `claude-fable-5` ("opus does, fable tells and reviews"). Usage-based router kept but default OFF; per-task overrides always win.
- **2026-08-24 — Agent Task API**: workers file follow-ups + coordinate cross-repo via `/api/agent/*` with per-run tokens. Full design + review verdict: `docs/agent-api-design.md`; agent-facing sheet: `docs/agent-instructions.md` (served at `/api/agent/instructions`).

- **2026-08-24 — Real-time UI**: everything flows over `/ws/events` (token-gated). The client refetches `/api/session` before every reconnect (per-boot token rotates on server restart) and calls `refresh()` on every WS open to close missed-event gaps. Live worker runs broadcast `run.updated` with fresh transcript stats every 20s; a `SessionStart` hook reports session/transcript identity at spawn so stats stream from the first tick.

- **2026-08-24 — Stack**: Node 24 + TS + Fastify 5 server, React 19 + Vite SPA, npm-workspaces monorepo. `tsx` in dev AND prod (no server build step); only the SPA is built.
- **2026-08-24 — Storage switch**: file-based (`server/data/config.json`), `sqlite` (better-sqlite3) default, `postgres` (pg) for external sync — Supabase works via its Postgres connection string (free tier: 500MB, pauses after ~1wk idle). Fixed `tm_` table prefix in both dialects so SQL strings stay identical; proposal payloads are TEXT (not JSONB) for the same reason.
- **2026-08-24 — No generic `transaction(fn)`** (adversarial review, blocker B1): better-sqlite3 transactions are sync-only; async callback would escape the transaction. Composite storage methods instead: `claimNextQueuedTask`, `acceptProposal`, `resolveChildCompletion`.
- **2026-08-24 — Worker = interactive `claude` in node-pty**, completion via `--settings`-injected Stop/SessionEnd hooks; `-p` mode rejected (not a usable terminal). Notification hook added (blocker B2) so permission prompts in hidden terminals surface as "needs attention" instead of deadlocking.
- **2026-08-24 — Terminal WS security** (blocker B3): bind 127.0.0.1, Origin check on upgrade, per-boot token required on `/ws/terminal`.
- **2026-08-24 — First Stop → `review`** by default (turn-end ≠ task-done; agent may have asked a question). Config `orchestrator.autoComplete` flips to `done`.
- **2026-08-24 — No auto-retry**: retrying a failed agent run on a half-edited repo is dangerous; manual Retry button only.
- **2026-08-24 — Caps** (user-mandated): 2 concurrent worker sessions; each worker's prompt instructs max 3 subagents (no CLI flag exists for a hard cap).
- **2026-08-24 — Permission mode `auto` is the worker default** (user decision): CLI supports `acceptEdits, auto, bypassPermissions, manual, dontAsk, plan`; we expose auto (everyday), acceptEdits (cautious), bypassPermissions (red switch).
- **2026-08-24 — Model + effort**: config defaults `agent.model`/`agent.effort` (CLI `--effort low|medium|high|xhigh|max`, verified) with per-task overrides (`tm_tasks.model/effort`, null = config default). Dropdowns in Config + task slide-over.
- **2026-08-24 — Session usage stats**: per run we record session_id + transcript_path (from hook stdin JSON, Phase 4) and compute duration, tokens in/out, cost USD (pricing table), and context-window % ("usage %" = share of the model's context consumed). Shown as chips in slide-over + Queue.
- **2026-08-24 — Model routing** (user rule): explicit task.model wins; tool/browser-testing tasks (keyword match: browser/playwright/e2e/screenshot/…) always use the fallback model (`claude-opus-5`); otherwise primary `claude-fable-5` while estimated usage < 85%, then fallback. Usage % is ESTIMATED from local `~/.claude/projects` transcripts over a trailing 5h window against a configurable token budget (`router.budget5hTokens`) — the CLI exposes no official account-usage API. Header shows the live estimate + routed model.
- **2026-08-24 — Worker env hygiene**: PTY env strips inherited `CLAUDE_CODE_*`/`CLAUDECODE` vars (a server started from inside a claude session would otherwise disable worker transcript saving) and sets `CLAUDE_CODE_FORCE_SESSION_PERSISTENCE=1` — transcripts feed run stats.
- **2026-08-24 — node-pty gotcha**: npm strips the exec bit from `prebuilds/*/spawn-helper` → `posix_spawnp failed`; root postinstall chmods it back.
- **2026-08-24 — auto mode + haiku**: CLI reports "auto mode unavailable for this model" for haiku and falls back to manual — use acceptEdits or opus/fable for unattended runs of small-model tasks.
- **2026-08-24 — review→done** is an explicit human action `POST /api/tasks/:id/complete` (design originally omitted it — review R13); queued tasks can be de-queued via cancel without the orchestrator (R12).
- **2026-08-24 — Analyze**: headless `claude -p --output-format json --json-schema`, read-only via `--disallowedTools Edit Write Bash` + `dontAsk` (NOT plan mode — it fights structured output). Parse the result envelope, not raw stdout. `maxBuffer` 64MiB.
- **2026-08-24 — Design system**: user-provided token sheet `docs/tm-design-tokens.html` is the single source of visual truth (`--tm-*` prefix, graphite ramp + phosphor teal accent, Bricolage Grotesque/Inter/JetBrains Mono, status hues mapped to the run lifecycle, 4px space scale, motion tokens). `web/src/theme.css` defines these tokens verbatim and every style resolves to them. Dark is the default theme regardless of OS preference; `blocked` (not in the sheet's lifecycle) borrows `--tm-status-attention`.
- **2026-08-24 — Sentry**: stub — `source`/`source_ref` fields, config slots, manual "create from Sentry ref" form. No API pull in v1.
